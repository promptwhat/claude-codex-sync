# claude-codex-sync (v1.4)

클로드 코드에 쌓아 둔 스킬과 규칙을 코덱스도 똑같이 쓰게 연결한다. 반대로 코덱스에만 있던 스킬도 클로드 쪽에 걸린다.

- **스킬**: 진짜 폴더가 있는 쪽이 원본이고, 반대쪽에는 링크만 건다. 파일이 한 벌이라 한쪽을 고치면 양쪽에 바로 들어간다.
- **규칙**: `AGENTS.md`가 원본이다. `CLAUDE.md`는 `@AGENTS.md` 한 줄로 그걸 불러오고, 클로드 전용 규칙만 그 아래에 둔다.
- 도구 = 이 스킬 폴더의 `scripts/ccsync.sh`. 지우는 건 install이 만든 링크뿐이고, 바꾸는 파일(CLAUDE.md)은 먼저 백업한다.

이 스킬이 맞추는 건 **스킬과 규칙**이다. 모델 자체의 차이는 그대로 남는다(코덱스는 GPT 모델로 돈다). 사용자에게 "코덱스가 클로드처럼 된다"고 말하지 않는다.
대화 기록·기억을 나누거나, 클로드가 하던 일을 코덱스에 넘기는 기능은 없다. claude.ai 웹 채팅에 올려서 쓰는 스킬도 아니다(내 컴퓨터의 클로드 코드에서 돈다).

## 준비물 (없으면 먼저 안내)

- 클로드 코드 설치·로그인: `curl -fsSL https://claude.ai/install.sh | bash` → 새 터미널에서 `claude` 실행 → 브라우저로 로그인.
- 코덱스 설치·로그인: `curl -fsSL https://chatgpt.com/codex/install.sh | sh` → `codex` 실행 → **Sign in with ChatGPT**. ChatGPT 데스크톱 앱의 코덱스를 써도 된다.
- 이 스킬 폴더 위치: `~/.claude/skills/claude-codex-sync/`. 아래 명령은 모두 이 경로 기준이다(다른 곳에 풀었으면 그 경로로 바꾼다).

## 순서

1. **점검부터.** `bash ~/.claude/skills/claude-codex-sync/scripts/ccsync.sh check` (프로젝트까지 보려면 뒤에 `--project <폴더>`). 결과를 쉬운 말로 요약해 사용자에게 보여 준다. ⚠️가 문제고 ℹ️는 참고다.
2. **설치.** `bash ~/.claude/skills/claude-codex-sync/scripts/ccsync.sh install` (+ `--project <폴더>`). 여러 번 돌려도 같은 결과가 나온다.
3. **설치가 멈춘 곳 처리.** 도구가 일부러 손대지 않고 남긴 경우들이다.
   - **CLAUDE.md와 AGENTS.md 내용이 다름**: 두 파일을 사용자에게 나란히 보여 주고 합친 AGENTS.md 안을 낸다. 클로드 전용 줄(클로드에만 있는 도구 이름 등)은 CLAUDE.md에 남길 몫으로 따로 표시한다. 사용자가 확인한 뒤에만 AGENTS.md에 쓰고 install을 다시 돌린다.
   - **CLAUDE.md가 다른 파일을 불러옴**(줄 하나든 문장 중간이든, `\ ` 공백 경로 포함. `코드` 표시 안과 `@계정명` 같은 말은 제외): 코덱스는 `@불러오기`를 못 읽는다. 불러오는 파일 내용을 본문으로 풀어 쓴 안을 사용자에게 보여 주고, 확인받은 뒤 install을 다시 돌린다.
   - **이름 겹침(양쪽에 같은 이름의 진짜 폴더)**: 어느 쪽을 남길지 사용자에게 묻는다. 남기지 않을 쪽은 지우지 말고 스킬 폴더 **밖**으로 옮긴다(스킬 폴더 안에 백업을 두면 코덱스가 같은 스킬을 두 개로 띄운다).
   - **`.claude/CLAUDE.md`를 쓰는 프로젝트**: 맨 위 `CLAUDE.md`로 옮기자고 제안한다.
   - **CLAUDE.md가 링크임**(dotfiles 등): 링크 너머 파일이 바뀌니 손대지 않는다. 링크를 풀지, 지금 구조를 유지할지 사용자에게 묻는다.
4. **다시 점검.** check를 돌려 ⚠️가 0인지 확인한다. 종료 코드: 0 = 문제 없음 · 1 = 손볼 곳 있음(⚠️) · 2 = 쓰기·복원 실패(❌). install·undo도 같은 코드를 돌려준다. ❌가 나오면 아무것도 성공했다고 말하지 않고 그 줄을 사용자에게 그대로 보여 준다.
   프로젝트에 생긴 `CLAUDE.md.ccsync-bak`은 커밋하지 않게 사용자에게 알린다(확인 끝나면 지워도 되는 백업).
5. **새로 열기 안내.** 클로드 코드와 코덱스를 둘 다 새로 열어야 바뀐 규칙이 들어간다. 프로젝트 CLAUDE.md가 프로젝트 밖 파일을 불러오면 클로드가 처음 한 번 허용 여부를 묻는다(거절하면 계속 꺼진 채로 남는다).
6. **두 앱에서 실제로 확인.** check는 파일 연결만 본다. 사용자에게 아래 질문을 클로드 코드와 코덱스에 **각각 새 창에서** 그대로 보내 보라고 안내한다. 두 앱의 답에 같은 규칙 내용과 같은 스킬 이름이 나오면 연결 끝이다.
   ```
   파일은 열지 말고, 지금 너에게 주어진 지침과 스킬 목록만 보고 답해. 1) 내 규칙에서 맨 처음 나오는 규칙 한 줄 2) 사용할 수 있는 스킬 이름 전부
   ```

## 코덱스에 넘기지 않을 스킬

`~/.claude/ccsync-ignore`에 스킬 폴더 이름을 한 줄에 하나씩 적으면 연결하지 않는다. 클로드에만 있는 도구 없이는 아예 안 도는 스킬을 여기 넣는다. check가 ℹ️로 그런 스킬을 알려 준다.

## 되돌리기

`bash ~/.claude/skills/claude-codex-sync/scripts/ccsync.sh undo`

install이 남긴 기록 전체(전역·프로젝트)를 한 번에 되돌린다. 걷어 내는 건 이 도구가 건 링크 중 지금도 같은 곳을 가리키는 것뿐이다. 되돌리다 실패한 항목은 기록에 남겨서, 원인을 고친 뒤 undo를 다시 돌리면 이어서 되돌린다. 설치 뒤 사용자가 불러오기 줄을 문장 안으로 옮기는 등 모양을 바꿨으면 파일을 건드리지 않고 ❌로 알린다. 그 줄을 지우고 AGENTS.md 내용을 붙여 넣으라고 안내한다. CLAUDE.md는 불러오기 줄 자리에 **지금의** AGENTS.md 내용을 풀어 넣어 되돌린다(설치 뒤에 고친 내용도 그대로 남는다). AGENTS.md가 그새 없어졌으면 설치 때 백업으로 되돌린다. AGENTS.md는 지우지 않는다.

## 폴더 배치 (도구가 만드는 모양)

| 무엇 | 원본 | 반대쪽 |
|---|---|---|
| 전역 규칙 | `~/.codex/AGENTS.md` | `~/.claude/CLAUDE.md`에 `@~/.codex/AGENTS.md` |
| 프로젝트 규칙 | `<프로젝트>/AGENTS.md` | 같은 폴더 `CLAUDE.md`에 `@AGENTS.md` |
| 전역 스킬 | 진짜 폴더가 있는 쪽 | `~/.claude/skills/<이름>` ↔ `~/.agents/skills/<이름>` 링크 |
| 프로젝트 스킬 | 진짜 폴더가 있는 쪽 | `.claude/skills/<이름>` ↔ `.agents/skills/<이름>` 상대 경로 링크(저장소를 옮겨도 유지) |

`CLAUDE_CONFIG_DIR`, `CODEX_HOME`을 바꿔 쓰는 사람은 그 폴더 기준으로 동작한다.

## 알고 쓸 조건과 한계

| 상황 | 일어나는 일 | 도구의 대응 |
|---|---|---|
| 규칙이 길다 | 코덱스는 규칙 파일을 `project_doc_max_bytes`(기본 32KiB)까지만 읽고 나머지는 말없이 버린다. 실측에서는 전역 AGENTS.md가 한도를 넘어도 프로젝트 AGENTS.md는 읽혔다 | 프로젝트 규칙(저장소 맨 위부터 그 폴더까지 코덱스가 고르는 파일 합계)이 넘치면 경고, 전역이 넘치면 참고로 알림. 줄이거나 `~/.codex/config.toml`에서 한도를 올린다 |
| `AGENTS.override.md`가 있다(전역 `~/.codex/`, 프로젝트 폴더, 또는 저장소 맨 위까지의 상위 폴더) | 코덱스가 같은 자리의 AGENTS.md 대신 그걸 먼저 읽어서, 클로드가 불러오는 AGENTS.md와 규칙이 달라진다 | install·check가 경고. 내용을 AGENTS.md로 합친다 |
| 저장소 맨 위~그 폴더 사이 상위 폴더에 CLAUDE.md(또는 `.claude/CLAUDE.md`)나 AGENTS.md 한쪽만 있다 | 그 폴더 규칙이 한 앱에만 적용된다(아래쪽에 CLAUDE.md가 있으면 클로드는 상위 AGENTS.md를 읽지 않는다) | check·install이 경고. 그 폴더도 `--project`로 잇는다 |
| 프로젝트에 AGENTS.md만 있고 CLAUDE.md가 없다 | 클로드 코드 v2.1.277 이상은 이때 AGENTS.md를 직접 읽는다. 단 그 폴더나 상위 폴더에 CLAUDE.md·`.claude/CLAUDE.md`·CLAUDE.local.md 중 하나라도 있으면 직접 읽지 않는다 | 경로에 클로드 규칙 파일이 있으면 경고, 없으면 참고(ℹ️). install로 불러오기 줄을 만들면 확실하다 |
| `CLAUDE.local.md`가 있다 | 개인용 클로드 규칙이라 코덱스에는 넘기지 않는다 | check가 참고(ℹ️)로만 알림. 둘 다 써야 하는 규칙이면 AGENTS.md로 옮긴다 |
| SKILL.md에 `name`이나 `description`이 없거나 비었다 | 코덱스는 둘 다 있어야 읽는다. 클로드는 읽지만 언제 쓸지 판단을 못 한다 | check가 경고. 머리말에 두 줄을 채운다 |
| 스킬이 클로드 전용 도구를 부른다 | 코덱스에서는 그 단계가 빠진다 | check가 ℹ️로 표시 |
| 원본 폴더를 옮기거나 지웠다 | 링크가 끊긴다 | check가 경고. 이 도구가 건 링크면 install이 정리하고, 사용자가 직접 건 링크는 같은 이름 스킬이 있어도 덮지 않고 알려만 준다 |
| CLAUDE.md의 코드블록·`코드` 안에 `@AGENTS.md` 예시가 있다 | 클로드는 그 줄을 불러오지 않는다 | 연결로 치지 않는다. 진짜 불러오기 줄이 있어야 "연결됨" |
| 경로에 공백이 있다 | `@불러오기`는 공백 앞에 `\`가 있어야 하고, 따옴표로 감싸면 안 불러온다 | 도구가 알아서 처리 |
| 데스크톱 앱 코워크 세션 | 링크된 전역 CLAUDE.md와 작업 폴더 밖 불러오기를 건너뛴다 | 코워크에서도 전역 규칙이 필요하면 불러오기 대신 실제 내용을 둔다 |
| claude.ai·데스크톱 앱 채팅 스킬 | `~/.claude/skills`와 따로라 연결되지 않는다 | 범위 밖. 앱에는 따로 올린다 |
| 클라우드 세션(클로드 웹·코덱스 클라우드) | 내 컴퓨터 폴더를 못 본다 | 저장소에 커밋한 프로젝트 규칙·스킬만 따라간다 |
| 윈도우 | 링크를 걸려면 관리자 권한이나 개발자 모드가 필요하다 | v1.4는 맥·리눅스(WSL 포함)만 지원 |

## 확인용 테스트

`bash ~/.claude/skills/claude-codex-sync/scripts/test_ccsync.sh`: 가짜 홈 폴더에서 설치 → 재설치 → 점검 → 되돌리기를 돌려 보고 `PASS`를 낸다. 진짜 설정은 건드리지 않는다.
